A rigorous line-by-line inspection of crates/doomterm_plate/src/paint.rs revealed critical layout defects where text strings can collide and overlap under realistic, hostile, or responsive inputs:

  1. Middle Panel Text Overflow (Vulnerability 1): In paint.rs lines 229, 233, and 235: 
    r.sm_text(spec.value_x, 12, &state.path, colors::VALUE, false);
    Strings are rendered starting at spec.value_x (182px) with zero truncation or boundary checks. While spec.value_chars is defined as 24 in spec.rs, it is never used during painting. Any file path or branch name longer than 24 characters (e.g. /home/cleadmon/Projects/Doom Term/..., 65 chars = 390px) spills far beyond the panel boundary (104 + 226 = 330px) directly into spec.zone_x (334px), catastrophically overlapping the waiting queue, count indicator, and status glyphs.

    r.sm_text(cx + 16, cy, &item.name, colors::VALUE, false);
r.sm_text(cx + col_w.saturating_sub(4), cy, &item.tag, colors::TAN_DIM, true);

If a session name is longer than the column width minus tag width (e.g. build-container-optimization), the characters of the name and the tag are painted directly on top of each other, and overflow into the next column or sandbox controls.
  3. Missing Status Glyphs (Vulnerability 3): In paint.rs line 275:

A. Mathematical Elimination of Middle Panel Text Overflow

To prevent middle panel values (AGENT, PATH, BRANCH) from ever spilling into the elastic waiting zone:

  • Implemented truncate_left(s: &str, max: usize) -> String in crates/doomterm_plate/src/spec.rs. When string length exceeds max, the string is truncated from the left with a leading ·· indicator, preserving the file name or branch leaf.
  • Bound middle panel values to spec.value_chars (24 characters). At ADV_SM = 6px per character, maximum value width is 24 × 6 - 1 = 143px.
  • Starting at spec.value_x = 182px, the rightmost painted pixel is 182 + 143 = 325px. The panel well ends at 104 + 226 = 330px, and the elastic zone begins at 334px.
  • Mathematical Guarantee: There is always a minimum 5px clearance inside the panel well, and a minimum 9px barrier before the elastic zone. Middle panel text can never touch or overlap the waiting queue.

B. Elimination of Waiting Queue Inter-Text Collision

To eliminate collision between session names and tags within waiting queue columns:

  • Implemented PlateSpec::waiting_row_box(&self, index: usize, tag: &str) -> Option<WaitingRowBox> computing exact pixel bounds for each row.
  • Derived available name room: name_room = (tag_x - (name_x + ROW_TAG_GAP + tag_w)) / ADV_SM. If name_room < WAITING_NAME_MIN (3 characters), the row is skipped rather than rendered with broken text.
  • Enforced name truncation: item.name.chars().take(box_info.name_room), guaranteeing that the name terminates at least ROW_TAG_GAP (4 pixels) prior to the tag start.
  • Enforced tag right inset: tag_x = x + w - 1 - ROW_EDGE_PAD, guaranteeing a 4-pixel breathing room from the column bevel or groove.

The following mathematical assertions govern all typography and layout across the entire Doom Term status plate engine:

[PROOF 1: MIDDLE PANEL VALUE EXTENT]

[PROOF 2: WAITING QUEUE INTER-ELEMENT SEPARATION]

Let name_x = cx + 19, ROW_TAG_GAP = 4, ROW_EDGE_PAD = 4.
Tag position is right-aligned at tag_x = cx + w - 1 - ROW_EDGE_PAD = cx + w - 5.
Let tag length be T characters, width tag_w = T × ADV_SM.
Tag starts at tag_start = tag_x - tag_w + 1.
Room allocated for name: name_room = floor((tag_x - (name_x + ROW_TAG_GAP + tag_w)) / ADV_SM).

name_end ≤ tag_x - ROW_TAG_GAP - tag_w - 1 = (tag_start - 1) - ROW_TAG_GAP.
Therefore, tag_start - name_end ≥ ROW_TAG_GAP + 1 = 5px.
