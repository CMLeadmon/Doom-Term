The app test target has existing hosted-service dependencies incompatible with the Doom Term feature set. Focused Rust tests import the production module directly; real application behavior is covered by the native smoke check. Updated app persistence/launch-config fixtures are committed, but their app test targets were not run. Full app/workspace tests and native Windows/macOS/WSL execution are not claimed here; the PR’s existing Linux, macOS and Windows build jobs provide the platform build gate.

Strict app-wide Clippy fails on main with 60 existing errors (baseline output). The feature passes app Clippy with only those baseline lint categories allowed, and the new production directory module passes strict Clippy. PowerShell quoting has unit coverage; actual PowerShell/WSL and non-POSIX remote operating systems were not exercised.

Reproduce the focused checks

./script/doomterm/test-tab-groups
python3 -m unittest discover -s script/doomterm -p 'test_group_persistence.py'
python3 -m unittest discover -s script/doomterm -p 'test_runtime_flags.py'
./script/doomterm/test-tab-groups --clippy
cargo build -p warp --bin doomterm --no-default-features --features doomterm,gui
./script/doomterm/test-tab-groups-gui --binary /absolute/path/to/target/debug/doomterm

The GUI runner requires Podman and localhost/doomterm-verify:ubuntu24.04 from the repository’s verification Containerfile. It uses a disposable profile and temporary directories. Install Fish for the executable quoting checks. See usage and verification instructions.
