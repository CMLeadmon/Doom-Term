Doom Term Sidecar

Warp’s shell at production density, carrying the Doom Term status plate and an agent rail — rebuilt from a measured screenshot, and interactive.

The app

Warp’s information architecture at real density — 13px mono, a 256px session list, a 400px review panel — with the plate docked across the bottom at ×3, and the rail floating top‑right. Everything the plate shows is read from the session you have selected, so it moves when you do. Both are drawn by plate.js, the archived tree’s renderer, shipped unmodified.

Click an agent, anywhere

The rail, a session in the list, or a row inside the plate’s own waiting well. The mark, the AGENT/PATH/BRANCH panel, the token table and the pane all follow together.

The plate is a control surface

The three chips toggle. The MODE cell cycles FULL → TREE → OFF. Regions come from plate.js’s own geometry, so a row it declined to paint is never clickable.

Drag the width

The readout above tracks the real numbers. Below 1824px the elastic centre has no room and the waiting well goes — that is zoneW = logical − 480 behaving as designed, not breaking.

Type into it

The composer takes text; Enter posts it and marks that agent busy, so you can watch the mark swell and go still. Tabs close, the review panel collapses.

How it was derived

The 1:1 rebuild of the production screenshot that every number below was measured from.

Before the app above could be normalised, the screen had to be understood. This is Warp rebuilt at 2100×1313 — the source capture is a 1× grab, confirmed by its 13px window buttons, so one image pixel is one CSS pixel and nothing needed resampling. The type here is huge because the source was shot at a marketing font size; the app above is that screen brought back to production density.

Screenshot vs rebuild

Drag the divider. The plate and rail are removed from the measured render — they are additions, and scoring them against a screenshot that never contained them would report a deficit that is really a feature.

Pixel agreement

Share of pixels whose worst RGB channel differs from the screenshot by no more than the stated amount. ±8 is “the same colour”; ±32 tolerates antialiasing on a glyph edge. Produced by scripts/measure.py on each run.

Where the difference is

Every differing pixel, brightness scaled to the size of the error, over the dimmed screenshot. What survives is almost entirely glyph interiors — letters in the right place, drawn by a different typeface.

Landmarks

The same detector run over both images: panel dividers by stepping the column median, text rows by ink banding, advance width by the spacing of glyph runs. Both columns are measured — neither is the value I built to.

Palette

Modal colour of the same flat patch in each image, with CIE76 ΔE between them. Below 1.0 is indistinguishable.

What the residual is

Typefaces — most of it

Warp ships its own faces; this page has JetBrains Mono and Inter, the closest pair on an allowed font host.

Metrics were matched rather than guessed: size and tracking are tuned so the measured advance is 18.2px, the reference’s own. Words start and end in the right place, which is why the heatmap shows hollow outlines — ink on ink, different contours.

Icons

Hand-drawn to the measured box. Right size, right place, but not Warp’s icon set — each one is a small cluster in the heatmap.

Clipped content

The review panel runs off the right edge of the source window, so the SQL is transcribed only as far as it is legible. Past the cut the two images diverge on text nobody can read in either.

The rail, and what it costs

An overlay reserves no layout, so on this screen it sat on the review panel’s controls. Those rows now step out from under it — nothing is unreachable — but the rail still floats over the right edge of the diff body, where the code is already clipped. A reserved gutter would avoid even that, at the cost of a strip of width.
